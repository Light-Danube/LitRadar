# Перше встановлення у Windows з вихідного ZIP-архіву GitHub

Ця інструкція призначена для архіву, завантаженого через **Code → Download ZIP** на GitHub. Завантажте гілку `main` і розпакуйте архів. У ньому є `cli.py`, `pyproject.toml`, `run_litbeacon_web.bat` і файли для розробників. Це **не** майбутній пакет релізу `LitBeacon-1.0.0-setup.zip`, що міститиме два файли. **Пакет релізу 1.0 ще не опубліковано.** Щоб спробувати ZIP із вихідним кодом, збирати wheel не потрібно.

## Перший запуск

1. За потреби встановіть **Python 3.12.x** із [python.org](https://www.python.org/downloads/windows/) разом із системним засобом запуску `py`. Сайт може пропонувати новішу версію: виберіть саме 3.12. У користувача працював Python 3.12.7. Повторно відкрийте PowerShell і перевірте `py -3.12 --version`. Для LitBeacon потрібен Python 3.11 або новіший; 3.12 — перевірена й рекомендована версія. Старий засіб запуску використовував `py -3`, який міг вибрати Python 3.9 і завершитися помилкою `TypeError: dataclass() got an unexpected keyword argument 'slots'`.
2. Розпакуйте архів GitHub у **нову папку з правом запису**, наприклад `Documents\LitBeacon-test`. Відкрийте папку, у якій безпосередньо лежать `cli.py` та `run_litbeacon_web.bat`. У рядку адреси Провідника введіть `powershell` і натисніть Enter. Не запускайте встановлення з вікна перегляду ZIP-архіву.
3. У відкритому PowerShell виконайте:

   ```powershell
   py -3.12 --version
   $env:LITBEACON_HOME = (Join-Path (Get-Location) 'user-data')
   .\run_litbeacon_web.bat
   ```

   Папка `user-data` відокремлює пробне встановлення від наявної бібліотеки. Засіб запуску створює `.venv`, встановлює залежності вебінтерфейсу й Textual TUI, ініціалізує пробну базу даних і запускає локальний вебсервер. Тести для розробки, пакети семантичних моделей та SDK хмарних LLM **не** входять до звичайного встановлення. Парсери для імпорту файлів необов’язкові. Якщо згодом знадобиться імпорт PDF/BibTeX, у цій папці виконайте `.\.venv\Scripts\python.exe -m pip install --no-cache-dir ".[annotations]"`. Для першого запуску потрібен інтернет, щоб pip завантажив залежності.
4. Відкрийте <http://127.0.0.1:8765>. Зупиніть сервер клавішами Ctrl+C. Щоб запустити його знову в **тому самому** вікні PowerShell, повторіть `.\run_litbeacon_web.bat`. У новому вікні спочатку знову встановіть `LITBEACON_HOME`. Папка `.venv` містить середовище Python, а `user-data` — пробну бібліотеку. Збережіть `user-data`, якщо хочете залишити пробні дані.

`setup_litbeacon.bat` виконує лише встановлення й залишає вікно з помилками відкритим навіть за запуску подвійним клацанням. Якщо вже існує старе або пошкоджене `.venv`, засіб запуску збереже його як `.venv-before-python312` і створить нове `.venv` із Python 3.12 (або 3.11). Він не переміщує й не видаляє бібліотеку. Якщо резервна назва вже зайнята, перейменуйте стару папку самостійно перед повторною спробою; спочатку закрийте програми, що використовують старе середовище. `run_litbeacon.bat` відкриває TUI, `run_litbeacon_cli.bat` — командну оболонку, а `run_litbeacon_telegram.bat` запускає необов’язкового бота після налаштування. Старі назви файлів запуску `litradar` залишилися для сумісності. ZIP із вихідним кодом не може оновити себе через Git: для оновлення завантажте новіший ZIP в іншу папку. [Встановлення з wheel/пакета ZIP](PACKAGE-SETUP.uk.md) призначене для готового пакета релізу або пакета, зібраного для перевірки.

## Якщо встановлення зупинилося

- Якщо `py -3.12 --version` не працює, встановіть Python 3.12 разом із засобом запуску `py` і повторно відкрийте PowerShell; `py --list` покаже встановлені версії. Python 3.13 може співіснувати з 3.12, але засіб встановлення вибере 3.12, якщо вона доступна. Якщо попередня невдала спроба створила `.venv` з іншим інтерпретатором, запустіть засіб повторно: він збереже старе середовище, перш ніж створити нове. Видаляйте лише `.venv` у цій новій папці й лише після перевірки, що в ньому немає потрібних файлів. Не видаляйте `user-data`, `data/`, іншу папку LitBeacon або наявну бібліотеку.
- Якщо pip повідомляє `Permission denied`, `No matching distribution`, помилку компілятора чи мережі/TLS, збережіть **назву першого пакета й рядки помилки**, а також результат `py -3.12 --version`. Запускайте встановлення з PowerShell, щоб вікно не закрилося. Звичайний засіб запуску не записує до кешу pip і не встановлює необов’язкові парсери файлів. Вихідний код зберігає бібліотеку в цій папці (або за адресою `LITBEACON_HOME`, якщо її задано), а не в `%LOCALAPPDATA%\LitBeacon`. Якщо помилка повториться, повідомте лише, чи шлях відмови містить `pip\Cache`, `Temp` або `LitBeacon`, без свого імені користувача. Якщо `.venv` лежить у захищеній папці або раніше створене адміністратором, також потрібна нова папка з правом запису. Встановлення потребує доступу до мережі та індексу пакетів.
- Щоб перевірити команду встановлення окремо, у папці з `pyproject.toml` виконайте `py -3.12 -m venv .venv`, а потім `.\.venv\Scripts\python.exe -m pip install --no-cache-dir ".[web,ui]"`. Далі виконайте `.\.venv\Scripts\python.exe -m pip check`, `.\.venv\Scripts\python.exe -m cli init` та `.\.venv\Scripts\python.exe -m cli web`. Для ізольованої пробної бібліотеки в цьому самому вікні PowerShell усе ще має бути задано `LITBEACON_HOME`.

Використовуйте звичайний обліковий запис у папці з правом запису: права адміністратора й ручне видалення кешу для встановлення не потрібні. Користувач повідомив про успішне встановлення з вихідного ZIP без прав адміністратора й окрему успішну перевірку двофайлового пакета у Windows. [Результати та перевірки, що залишилися](LOCAL-1.0-RELEASE-CHECKLIST.md). Повідомляйте про помилки без особистої бази даних, `.env`, токенів чи приватних журналів.
