# Fresh Windows install from GitHub's source ZIP

Use this page if you chose GitHub's **Code → Download ZIP**. Download `main` and extract it. The ZIP contains `cli.py`, `pyproject.toml` and `run_litbeacon_web.bat`, plus developer files. It is different from the future two-file `LitBeacon-1.0.0-setup.zip` release asset. **No 1.0 release asset has been published yet.** You do not have to build a wheel to try the source ZIP.

## First launch

1. Install **Python 3.12.x** from [python.org](https://www.python.org/downloads/windows/) with the Windows `py` launcher. The site may suggest a newer version; select 3.12 deliberately. Python 3.12.7 worked for the user. Reopen PowerShell and run `py -3.12 --version`. LitBeacon needs Python 3.11+; Python 3.12 is the tested/recommended choice. The old launcher used `py -3`, which could choose Python 3.9 and fail with `TypeError: dataclass() got an unexpected keyword argument 'slots'`.
2. Extract the GitHub ZIP into a **new, writable** folder (for example, `Documents\LitBeacon-test`). Open the folder that directly contains `cli.py` and `run_litbeacon_web.bat`. In File Explorer's address bar type `powershell` and press Enter. Do not run setup from inside the ZIP viewer.
3. In that PowerShell window, run:

   ```powershell
   py -3.12 --version
   $env:LITBEACON_HOME = (Join-Path (Get-Location) 'user-data')
   .\run_litbeacon_web.bat
   ```

   The `user-data` directory keeps this test separate from an existing library. The launcher creates `.venv`, installs the web and Textual TUI dependencies, initializes the trial database, then starts the local browser server. Development tests, semantic-model packages and cloud LLM SDKs are **not** part of this normal setup. File-import parsers remain optional: later, from this folder, run `.\.venv\Scripts\python.exe -m pip install --no-cache-dir ".[annotations]"` if you need PDF/BibTeX imports. The first run needs internet access for pip dependencies.
4. Open <http://127.0.0.1:8765>. Stop with Ctrl+C. For another run in the **same** PowerShell window, use `.\run_litbeacon_web.bat` again; in a new window, set `LITBEACON_HOME` again first. The folder's `.venv` is the environment; `user-data` is the trial library. Keep `user-data` if you want to retain trial data.

`setup_litbeacon.bat` performs just the setup step and leaves errors visible when double-clicked. If an older or broken `.venv` exists, the launcher keeps it as `.venv-before-python312` and creates a clean `.venv` with Python 3.12 (or 3.11). It never moves or deletes your library. If that backup name already exists, rename it yourself before retrying; close programs using the old environment first. `run_litbeacon.bat` opens the TUI; `run_litbeacon_cli.bat` opens a CLI shell; `run_litbeacon_telegram.bat` starts the optional bot only after you configure it. Old `litradar` launcher filenames remain as compatibility aliases. A source ZIP cannot update itself with Git; download a newer source ZIP into another folder when needed. The packaged [wheel/setup ZIP route](PACKAGE-SETUP.md) is for a built release asset or a reviewer-built bundle.

## If setup stops

- If `py -3.12 --version` fails, install Python 3.12 with the `py` launcher and reopen PowerShell; `py --list` shows installed versions. Python 3.13 can coexist, but setup selects 3.12 when available. If an earlier failed run created `.venv` with another interpreter, rerun the launcher; it preserves the old environment before creating a new one. You may remove only that new folder's `.venv` after confirming it holds no files you need; do not delete `user-data`, `data/`, another LitBeacon folder, or an existing library.
- If pip reports `Permission denied`, `No matching distribution`, a compiler error, or a network/TLS error, copy the **first package name and error lines**, plus `py -3.12 --version`. Run from PowerShell so the window stays open. The user reported a permission denial under `AppData\Local\pip\Cache\wheels\...` during an optional `bibtexparser` install. The normal launcher now avoids pip cache writes and optional file parsers; on 2026-10-18 the user reported a successful fresh PR #43 source-ZIP setup and web launch without administrator rights. Its source checkout stores library data in this folder (or the `LITBEACON_HOME` you set), not in `%LOCALAPPDATA%\LitBeacon`. If the failure persists, identify whether the denied path is under `pip\Cache`, `Temp` or `LitBeacon` without sharing your username. A protected/previously administrator-owned `.venv` also needs a new writable folder. The install needs network/package-index access.
- To isolate the install command, run `py -3.12 -m venv .venv`, then `.\.venv\Scripts\python.exe -m pip install --no-cache-dir ".[web,ui]"` from the folder containing `pyproject.toml`. Follow with `.\.venv\Scripts\python.exe -m pip check`, `.\.venv\Scripts\python.exe -m cli init` and `.\.venv\Scripts\python.exe -m cli web`. The same PowerShell window must still have `LITBEACON_HOME` set for the isolated trial.

On 2026-10-18 the user reported a successful Windows source-ZIP setup with Python **3.12.7** after manually deleting the old `.venv` and Python cache folders, then running setup as administrator: a new `.venv` was created and the web workspace launched. A normal user session in a writable folder should suffice; cache deletion and administrator rights are not setup requirements. The new automatic environment-preservation path still needs native Windows verification. This confirms the user-reported source path, not an installed-wheel/setup-ZIP test. Report an error without including your personal database, `.env`, tokens or private logs.
