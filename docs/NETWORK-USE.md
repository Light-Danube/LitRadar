# Network use and the local-only boundary

LitBeacon keeps its authoritative library in local SQLite. “Local-only” describes storage and the supported localhost web launch; it does not mean every optional workflow works without internet. Reading/editing saved papers, notes, evidence, histories, graphs and local exports does not require a provider account. See [installation and configuration](USER-GUIDE.md#installation), [logging](LOGGING.md) and [the loopback boundary](archive/release-1.0/evidence/GATE4-LOCAL-BOUNDARY.md).

| Operation and trigger | Destination and information sent | Boundary and source evidence |
| --- | --- | --- |
| Explicit CLI/TUI discovery; scan jobs previously installed/enabled by the user | OpenAlex, Semantic Scholar and arXiv receive search terms, filters/limits and configured provider credentials where applicable. | [Provider registry/cache](../sources/registry.py), [OpenAlex](../sources/openalex.py), [Semantic Scholar](../sources/semantic_scholar.py), [arXiv](../sources/arxiv.py), [scan execution](../research_digest.py). Valid cached searches can avoid requests; cache misses/expiry can contact providers. An enabled scheduled scan runs without another interactive confirmation. |
| Research/CLI venue lookup and source-scoped search | OpenAlex receives venue/query text, concrete source ID, year/page filters and optional API key. | [Venue adapter](../sources/venues.py), [cache and ingestion](../venue_discovery.py), [Research API](../web/research_api.py). Lookup/search is explicit; choosing a quick-topic preset or opening the page does not issue a scholarly request. Refresh may bypass cache. |
| Explicit citation expansion/refresh | OpenAlex/Semantic Scholar receive paper identifiers, relation direction and bounded limits; configured API credentials may accompany requests. | [Citation workflow](../citation_intelligence.py). Viewing the stored graph is local; expanding it can fetch new observations. |
| Explicit offline PDF download | Provider/publisher/repository PDF hosts receive HTTP requests for selected URLs; redirects can reach other hosts. Optional Unpaywall receives DOI and configured contact email to resolve legal-OA leads. | [Offline downloader and OA cache](../offline.py). Unpaywall is not queried without DOI/email. Saved PDFs and reading bundles remain local; selecting an online download is a network action. |
| Explicit opening of an online paper/DOI link | The system browser contacts the selected website/DOI resolver and any destinations it redirects to. | [CLI local-PDF/online open behavior](../cli.py), [web paper actions](../web/static/app.js). Browser traffic is outside LitBeacon's provider transport. |
| Optional Telegram listener/chat discovery and commands | Telegram Bot API receives the bot token, polling/menu requests, chat IDs, replies and content explicitly requested through commands. | [Listener/menu](../telegram_bot.py), [chat discovery/delivery](../research_digest.py), [operator limits](TELEGRAM-TROUBLESHOOTING.md). Starting the listener sets its command menu and polls continuously; it is not started by ordinary local library use. |
| Explicit Telegram digest send, or a previously enabled scheduled digest | Telegram receives the rendered digest: selected titles/metadata/abstract excerpts, reading queue and optional stored overlap-assessment excerpts. | [Digest construction/delivery](../research_digest.py), [scheduled dispatch](../cli.py). Preview is local. Scheduled delivery uses configured credentials; without Telegram configuration the scheduled digest saves a local report. Digest overlap processing can reuse stored LLM assessments; it does not itself call an LLM. |
| Explicit CLI `assess --provider openai\|anthropic` | The selected provider SDK receives paper title/abstract/venue, keyword/semantic scores, matched groups and research-profile description/groups. | [CLI assessment](../cli.py), [exact prompt](../llm/assessment.py), [provider clients](../llm/providers.py). Invoking the command is the opt-in; it has no separate browser-style consent checkbox. Personal notes, evidence worksheets and uploaded files are not fields in this prompt. |
| Web fresh inference with consent and provider/model selection | OpenAI/Anthropic, or the selected Ollama endpoint, receives only bounded stored title (2,000 characters) and abstract (10,000), plus the instruction/language prompt. | [Fresh-inference action](../web/annotation_actions.py), [provider clients](../llm/providers.py). Per-request consent is required. Notes, profile, evidence and uploads are excluded. Stored-assessment/local-prompt suggestions do not make fresh provider calls. |
| Optional Ollama inference | Default `http://localhost:11434/api/chat`; programmatically configured `OllamaProvider.base_url` can point elsewhere. Payload follows the invoking CLI/web prompt described above. | [Ollama client](../llm/providers.py). Standard provider selection supplies the default endpoint; the configurable client is not a guarantee of loopback-only inference. The selected model must be provisioned in Ollama separately. |
| Local semantic ranking/exploration | Encoding runs locally. Legacy CLI search/fixture ingestion and TUI online search request semantic ranking by default; scans default to keyword-only unless enabled. | [Legacy embedder](../ranking/embeddings.py), [CLI defaults](../cli.py), [TUI search](../ui.py), [pipeline fallback](../pipeline.py). The loader now uses `local_files_only=True` and `trust_remote_code=False`: missing local/cached weights cannot trigger an automatic download, and ordinary ranking callers fall back to keywords. Web semantic exploration is separately OFF by default and requires an existing local model path, local-only loading and safetensors: [web embedder](../ranking/semantic_workspace.py), [setup/limits](SEMANTIC-WORKSPACE.md). |
| Installation, updates and model provisioning | Package indexes/dependency hosts, configured Git remote and any model source the user separately chooses. | [Package setup](PACKAGE-SETUP.md), [Windows source ZIP](WINDOWS-SOURCE-ZIP.md), [updater](../update_litbeacon.sh). Installation/update needs network unless dependencies are supplied locally. Normal Windows setup installs web/TUI/file-import extras; semantic, LLM, development and browser-test dependencies require separate opt-in. Provision trusted model files separately before semantic use; `--no-semantic` keeps supported CLI search/fixture ingestion keyword-only. |

The shipped web shell loads HTML/JS/CSS/icons from the local server, with no production CDN or mandatory Node build: [HTML assets](../web/index.html). The reviewed application paths contain no mandatory telemetry sender. This is a scoped source review, not a guarantee about third-party SDKs, package installers, model servers, browser extensions or future dependencies. SDK/network proxy and endpoint configuration can also affect the actual destination.

The server has no account/authentication layer. Direct Uvicorn launch or changed Docker publication can bypass the supported CLI loopback restriction; loopback alone is not Origin/Host/CSRF protection. Provider requests may disclose research interests even when the library remains local. Keep credentials out of diagnostics; [logging policy and remaining scope](LOGGING.md) describe what is sanitized and what remains outside that guarantee.
