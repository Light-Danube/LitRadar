# Джерела, метод і достовірність

Актуалізація 2026-10-13: [Phase 1 реалізована як кандидат для review](phase-1.md); [офіційні публічні джерела конкурентів прочитані повторно](live-review-2026-10-13.md). Початкові обмеження й концепт нижче збережені як історія дослідження. Hands-on конкурентів і browser visual acceptance залишаються відкритими.


## Рівні доказів

| Позначення | Значення |
| --- | --- |
| A | Перевірено в поточному коді, тестах або наявних скриншотах LitBeacon |
| B | Відомий продуктовий підхід / стандарт; актуальна зовнішня сторінка в цій сесії недоступна |
| H | Дизайн-гіпотеза або ціль для майбутнього тестування |

Не проводили інтерв'ю, опитування, A/B-тести, аналіз telemetry чи платних конкурентних акаунтів. Немає підстав оголошувати виміряне підвищення швидкості, конверсії чи задоволеності. Персони — робочі гіпотези. Усі назви та дані публікацій у концепті — синтетичні.

## Внутрішні джерела A

- `web/index.html`: навігація, мова, skip-link, live region, структура оболонки.
- `web/static/app.js`: фактичні маршрути, події, чернетки, пошук, збереження, граф і розклад.
- `web/static/styles.css`: шрифти, кольори, компонування, scroll-контейнери, адаптивність.
- `web/static/locales.js`: EN/UK, повідомлення, значення наукових термінів.
- `web/static/graph-tools.js`: layout та SVG/GraphML export.
- `workspace_web.py`, `web/annotation_actions.py`: контракти API, валідація, provenance, обмеження.
- `tests/test_workspace_web.py`, `tests/test_workspace_v08.py`, `tests/test_annotation_provenance.py`, `tests/test_web_frontend.cjs`: наявне функціональне покриття.
- `docs/archive/gate1/screenshots/workspace-uk-graph.png`, `citation-map-provenance.png`, `annotation-provenance.png`: історичні ілюстрації наявного інтерфейсу; не нові скриншоти й не повна перевірка актуального рендерингу.

## Протокол завершення конкурентного дослідження

1. Відкрити S1–S8, зафіксувати URL після redirect, дату, тип доступу та версію/план, якщо видимі. Не створювати платні підписки без окремого дозволу.
2. Для кожного релевантного продукту виконати порівнювані завдання: знайти роботу, переглянути контекст, зберегти/організувати її, повернутися до попереднього списку; для графових продуктів — пояснити значення зв'язку та перейти до джерела. Позначити N/A для непідтримуваних завдань.
3. Розділяти реальний hands-on, публічне demo, документацію та маркетингову сторінку. Скріншот landing page не доводить ефективність продуктового сценарію.
4. Записати кроки, affordances, feedback, recovery, keyboard path, текстові розміри, тему й viewport. Знімки зберігати лише без персональних даних; для публічного звіту використовувати власні схеми з атрибуцією, а не копіювати чужі екрани без перевірки прав.
5. Перевірити світлу/темну тему, 1440/1024/390 px, 200% zoom, довгі назви й кілька джерел одного зв'язку там, де доступно.
6. Оновити таблицю конкурентів: замінити B на підтверджені спостереження з конкретним джерелом; зняти або виправити непідтверджені припущення. Не присвоювати числові usability-рейтинги без спільного тестового протоколу.

Публікація фінального market research вимагає завершення цього протоколу. Специфікація LitBeacon уже придатна для обговорення, бо її функціональна основа перевірена локально.
