# Дослідження ринку та UX-напрям LitBeacon

Актуалізація 2026-10-13: [Phase 1 реалізована як кандидат для review](phase-1.md); [офіційні публічні джерела конкурентів прочитані повторно](live-review-2026-10-13.md). Початкові обмеження й концепт нижче збережені як історія дослідження. Hands-on конкурентів і browser visual acceptance залишаються відкритими.


## 1. Висновок для продукту

LitBeacon варто розвивати як **особисте робоче місце для читання й перевірки літератури**: знайти роботу у власній бібліотеці → зрозуміти її контекст → записати власне спостереження → перевірити джерело/зв'язок → повернутися до черги читання.

Візуальний центр — назва, текст і дослідницька нотатка. Граф, релевантність, provenance та автоматичні підказки підтримують це завдання. Локальне зберігання, прозоре походження матеріалів, EN/UK і явні межі автоматизації дають зрозумілу позицію серед менеджерів бібліографії, discovery-сервісів та AI-інструментів. Це позиційна гіпотеза H, не доказ незайнятої ринкової ніші.

Рекомендований стиль: **Quiet Research / Спокійне читання**. Повноцінні світла і темна теми, читабельний текст, мало декоративних градієнтів, послідовні контроли, збережений контекст переходів. Вибір теми за замовчуванням підтвердити тестом; не примусово переключати на світлу всіх поточних користувачів темної версії.

### Синтез для рішення

1. **Від бібліографічних менеджерів** — передбачуваність об'єктів і навігації, а не максимальна кількість колонок.
2. **Від reading-продуктів** — ритм тексту й відокремлення читання від адміністрування.
3. **Від discovery-продуктів** — збереження стартового контексту й зрозуміла семантика зв'язку.
4. **Від evidence-продуктів** — джерело, метод створення і межі довіри поруч із твердженням.

Продуктова обіцянка для перевірки: «Читайте, пов'язуйте та перевіряйте літературу у власному дослідницькому просторі». Уникати слоганів про автоматичне визначення новизни, якості чи повне покриття літератури.

Серйозність нижче — експертна оцінка впливу, не результат користувацького тесту. P0 — передумова функціонального збереження; P1 — перший інкремент; P2 — після основних сценаріїв.

| --- | --- | --- |
| `.paper-title` 13 px; `.paper-meta` 10 px; `.abstract` 12 px; provenance переважно 12 px | Довгі назви, українські рядки й джерела вимагають зайвого зусилля | P1: назва списку 16–18 px; основний текст 16 px; метадані 13–14 px |

| При <1050 px список і detail стають вертикальними | Публікація може відкритися нижче довгого списку; потрібна перевірка в браузері | P1: явний мобільний detail-view; Back відновлює пошук, вибір і scroll |
| Overview завжди показує CLI-onboarding разом зі статистикою | Досвідчені користувачі повторно бачать стартові інструкції | P2: порожня бібліотека — розгорнута допомога; наповнена — компактний доступ «Як додати роботи» |
| Значення relevance відображається як `%` без локального підпису в рядку | Його можна сприйняти як упевненість або якість | P1: «Релевантність 82/100» + пояснення; жодних «82% достовірності» |
| Пошук повертає до 200 items, але count може бути більшим | Враження, що видно весь результат | P1: показувати «Показано 200 із N»; pagination потребує окремого API-рішення, не маскувати це infinite scroll |
| Панель графа містить фільтри, масштабування, три експорти, довгу легенду | Canvas відсувається вниз і втрачає роль робочої області | P1: постійна коротка toolbar; параметри у відкривній панелі; індикатор активних фільтрів; один export-menu з усіма 3 форматами |
| Панель вибраного вузла розташована під графом | Зміни вибору можуть бути поза поточним viewport | P1: правий inspector на desktop, доступна панель під canvas на narrow; фокус не стрибає самовільно |
| Research notes, JSON import, extraction, ручні й автоматичні annotations розміщені послідовно | Важко відділити власну думку від джерела й підказки | P1: вкладки/секції «Опис», «Мої нотатки», «Матеріали та походження», «Історія»; жодна функція не зникає |
| Є inline editors, revision conflict API, тимчасові чернетки в JS state | Ререндеринг, тема чи нові вкладки можуть втратити незбережений текст | P0: контракт чернеток, conflict UI і приймальні сценарії перед візуальним переносом |

Позитивні основи A, які потрібно зберегти: п'ять стабільних розділів; EN/UK із persisted preference; skip-link, visible focus, клавіатурні shortcuts; локальний API; opt-in generation; provenance; пагінація історії/annotations; bounded graph; explicit save; помилки та повторна спроба.

## 5. Візуальні напрями та вибір H

| Напрям | Переваги | Компроміс | Рішення |

| **Quiet Research**: нейтральний світлий canvas, білі поверхні, slate/teal, парна темна тема | Найкраще відповідає довгому читанню, не сперечається з науковими даними | Потрібно ретельно налаштувати ієрархію без сильних рамок | Рекомендований |

### Типографіка й простір

- Перший інкремент: системний font stack із кирилицею, без зовнішніх шрифтів/CDN. Не вважати Inter завантаженим лише через його назву в CSS.
- Основний текст 16 px / line-height 1.55–1.65; long-form область 60–72ch. Числа — стартова специфікація для тестування.
- Назва екрана 28/34; назва публікації в detail 24/32; у списку 16/24 або 18/26; метадані 13/20–14/22. Не зменшувати важливий текст до 10 px заради щільності.
- Комфортна й компактна щільність змінюють відступи/кількість другорядних рядків, не приховують функції й не зменшують читабельність нижче затвердженого мінімуму.
- Spacing scale: 4, 8, 12, 16, 24, 32, 48 px; радіуси 8 для controls, 12 для великих панелей. Тінь лише там, де показує накладання.
- Іконки — локальні узгоджені SVG; у важливих дій є текстова назва. Статус передається словом та формою/іконкою, не лише кольором.

## 6. Архітектура екранів

```text
LitBeacon
├─ Огляд: продовжити читання / нові роботи / статистика / допомога
├─ Бібліотека: пошук + статус + сортування → список → публікація
│  ├─ Опис: назва, автори, abstract, джерело, релевантність
│  ├─ Мої нотатки: статус, теги, текст, явне збереження
│  ├─ Матеріали та походження: записи, імпорт, extraction, opt-in
│  └─ Історія: попередні дослідницькі нотатки, load older
├─ Граф цитувань: стартова робота + фільтри + canvas + inspector + export
├─ Групи публікацій: евристичні групи з поясненням основи
└─ Заплановані завдання: scan/digest config + OS-обмеження + дії
```

Назви ключів/маршрутів не змінюються; «Матеріали та походження» — кандидат на локалізований заголовок, а не новий storage channel. В українській мові слово «анотація» зараз означає і abstract, і annotation: для description використовувати «Анотація публікації», для supplemental records — «Додаткові матеріали» з чіткими типами. Перевірити словник на користувачах перед перейменуванням усіх labels.

### Бібліотека й деталі

Desktop ≥1280 px: навігація 208–224 px, список 360–440 px, detail займає решту; ширина тексту обмежена, а не розтягнута на весь монітор. Назва може займати 2–3 рядки; повна назва завжди доступна в detail, tooltip не є єдиним способом читання.

1024–1279 px: компактніша навігація; якщо detail не вміщує ≥480 px, відкривати його окремим основним екраном. <768 px: один основний pane; кнопка «До результатів» відновлює запит, статус, сортування, selected id і scroll. Після відкриття focus переходить до заголовка detail; після Back — до відповідного рядка.

Вкладки не мають втрачати draft. Sticky save-bar з'являється лише за наявності змін; повідомляє «Є незбережені зміни», зберігає через той самий PATCH. Автозбереження в першому редизайні не вводити. Помилки збереження показувати поряд із формою й утримувати введений текст.

### Граф

- Canvas отримує доступну площу; inspector показує selected paper і зв'язки без прокрутки далеко вниз на desktop.
- В toolbar залишити «Фільтри (N)», легенду типів, масштаб і «Експорт». Відкриті фільтри містять усі поточні параметри; активні chips і кнопка reset видимі при закритій панелі.
- Cites — спрямована стрілка від citing до cited; related — ненапрямлена пунктирна лінія. Кожне правило має текстову легенду.
- Виділення вузла не запускає discovery. «Відкрити публікацію» і «Дослідити це оточення» лишаються різними діями.
- Provenance показує всіх providers і timestamps, не лише «головний» provider. Unknown year, seed поза діапазоном і ліміт 80 вузлів у web мають явні пояснення.
- Експорт містить поточний **відфільтрований граф**, як зараз, а не обрізаний viewport після pan/zoom. SVG, GraphML і JSON зберігаються окремими виборами.
- Додати альтернативу drag: кнопки переміщення/keyboard controls та текстовий список зв'язків. Не змінювати алгоритм layout у першому візуальному PR.

### Огляд, групи, розклад

Огляд підсвічує найближчу дію, не множить vanity metrics. Групи показують причину об'єднання («Тег», «Видання», «Спільні терміни») та застереження про евристику. Число робіт у групі не має означати, що всі показані: нині preview обмежений першими шістьма.

Розклад зберігає окремі scan/digest, підтвердження видалення та встановлення default jobs. Повідомлення після дії пояснює фактичний результат на поточній OS; «прапорець увімкнено» не замінює перевірку OS scheduler.

## 7. Доступність і локалізація

Ціль — WCAG 2.2 AA з ручною перевіркою; сертифікованої відповідності поки немає. Звичайний текст ≥4.5:1; великий ≥3:1; необхідні межі controls/графічні об'єкти ≥3:1. Design target для основних touch actions — 44×44 CSS px; нормативний мінімум 2.5.8 AA — 24×24 із винятками, не плутати ці вимоги.

Підтримати keyboard-only, visible/unobscured focus, 200% text zoom, reflow на 320 CSS px для звичайного контенту, override text spacing і reduced motion. Двовимірний граф може мати спеціальні правила reflow, але повинен мати доступну текстову альтернативу. Tooltip дублює пояснення, а не замінює назву чи інструкцію.

Зберегти Alt+1…5, `/`, Ctrl+Enter; додатково перевірити конфлікти з OS/browser/assistive technology. У меню, tabs і drawer реалізувати очікувані keyboard patterns, Escape і повернення фокуса. Не оголошувати весь довгий екран повторно після кожного введення в пошуку.

EN/UK рівноправні. Перевірити довші українські кнопки, 1/2/5 записів, формат дат і часовий пояс, лапки/апострофи, 120–200-символьні назви. Контент публікацій автоматично не перекладати. Не перекладати storage enums, API keys, `LITRADAR_*`, database paths чи CLI-команди.

## 8. Що свідомо винесено за межі редизайну

Не є поточними web-функціями: зовнішній scholarly search у браузері, PDF-reader/highlighting, нові LLM-виклики, semantic clusters, колекції/спільні проєкти, deletion/restore history, довільне редагування scheduler times, повний імпорт бібліографії. Не додавати їхні активні кнопки лише для красивого макета. Усі можуть мати окремі roadmap-інкременти після збереження й перевірки поточного web.
