# LitBeacon multilingual and local discovery: Phase 0 audit

Audit date: **2026-10-21**. Repository: `Light-Danube/LitRadar`. This is a read-only repository/provider audit and a proposal for focused Draft PRs. It does not certify a release, provider permission, or implemented import functionality.

## Scope and decisions

The user's direct request supplies three distinct requirements: Ukrainian-language publications, publications from Ukrainian scholarly venues/institutions, and the user's explicitly selected local research files. Query language, metadata language, full-text language, journal country, author affiliation and interface locale are separate concepts.

The attached 2026-10-20 brief supplies detailed requirements and proposed workflows. Its provider table explicitly lacked independent API verification; its examples are not evidence of existing product functionality. The direct request governs authorization. On 2026-10-21, the user accepted an initial **OpenAlex metadata-language filter with an explicit explanation**, after learning that the documented field does not guarantee full-text language. This does not approve a new Ukrainian provider pilot.

| Requirement | Baseline | Next step | Limitation |
| --- | --- | --- | --- |
| Ukrainian-language discovery | Ukrainian query text accepted; no language filter | Explicit OpenAlex metadata-language filtering, `uk`/`en`/any | Metadata language is not confirmed publication/full-text language |
| Ukrainian scholarly sources | Explicit OpenAlex source lookup and primary-source search | Preserve source identities; investigate one permitted provider | No complete national coverage or new adapter certified |
| Personal local files | Stored-library search and annotation import for an existing paper | Separate opt-in bibliography-import design | General bibliography/PDF ingestion, OCR and folder watching not implemented by this audit |

### New-provider gate

No new Ukrainian candidate passes every gate. Require a named service/operator, exact officially documented endpoint and permitted use, metadata license/harvesting terms, auth, documented quota or agreed conservative bound, stable identifiers, metadata samples, pagination/deletion behavior and a bounded permitted live smoke. Missing published limits are not permission for unlimited harvesting. User approval follows this concrete dossier; the metadata-language approval does not authorize a provider pilot.

For an allowed OAI pilot, validate `Identify`, `ListMetadataFormats`, selected set, `GetRecord`/`ListRecords`, opaque resumption tokens, deleted headers and empty/error results against the [OAI-PMH specification](https://www.openarchives.org/OAI/openarchivesprotocol.html). Do not assume DOI/language fields exist. OAI harvesting is not an arbitrary full-text search API; any local mirror must be bounded and explicit.

### Phase 1 contract

Name the capability **metadata-language filtering**, rather than implying verified publication language. OpenAlex supports the documented filter; mark other built-ins unsupported by this implementation until their semantics are separately verified. Any/unspecified preserves old requests without additional calls. A filtered mixed-provider selection must fail clearly or require a separate explicit unfiltered choice. Do not silently post-filter a broad top-N response or relax the filter after warning.

Retain raw language, normalized recognized value or `unknown`, provider and interpretation together. Missing metadata stays unknown regardless of title script. Preserve observations across canonical cross-provider updates; `raw_json` alone cannot do that. Prefer backward-compatible optional fields/defaults or explicit provider observation data. Version filtered cache identity; keep original query/applied filters in snapshots. A separately selected UK/EN example uses keyword terms for the existing emotion/sarcasm/context domain without changing the default profile. Use explicit `--no-semantic`: profile weights alone do not establish that every caller avoids model loading. Do not promise translation, morphology, inflection coverage or neural Ukrainian relevance.

### Phase 2 local bibliography design

1. **Selection:** individually chosen BibTeX/RIS files or uploaded bytes first. A later folder mode is explicit and nonrecursive by default. No home scan, link following, resolver/model call or watcher. Uploaded filenames remain labels.
2. **Proposed bounds:** 20 files, 5 MB/file, 20 MB aggregate, 1,000 records/preview, 30-second batch budget. Optional PDF at most 50 pages and bounded extracted text. These are design proposals, not existing product limits; benchmark before finalizing. Reject archives initially.
3. **Paths:** reject symlinks/hard links/device files and Windows junction/reparse points in every component. Validate a chosen allowed root and file type; safely open and compare file identity to reduce path-swap races. Parse validated bytes, not reopened parser paths/URLs. Never move/delete/overwrite originals. POSIX checks do not establish Windows behavior.
4. **Parsing:** map title/authors/date/DOI/URL/journal/abstract/language/type and retain raw fields/parser version. Unknown stays unknown. PDF text is not authoritative bibliographic identification; low-confidence/missing metadata needs review or skip. Encryption/scans without text fail explicitly; no OCR fallback.
5. **Preview/commit:** display new/duplicate/conflict/skipped/failed, canonical candidate, changes and provenance; no preview writes. Bind commit to selected content hashes and current record fingerprint/revision. Recompute stale/changed previews instead of silently applying them.
6. **Merge:** reuse identity normalization/lookup, but preserve canonical metadata on duplicates and append import observations. Require explicit conflict choices; retain notes/tags/status/annotations/evidence/citations/ranking. An absent DOI or ambiguous title does not justify the wrong merge. Do not blindly use overwrite-prone upsert.
7. **Provenance/privacy:** generated batch ID, content hash, format/record key, parser/version/time, safe optional filename. Keep original metadata apart from canonical values; avoid absolute personal paths in public exports. Default metadata-only ingestion. Define explicit copy/reference options and missing-file status; missing originals must not break stored citation metadata.
8. **Recovery:** transactionally commit a validated batch and journal created IDs/observations. Undo only unchanged importer-owned additions; retain later user edits/shared records. Offer trusted pre-import backup for full recovery. Cover journal/retained files in backup contracts; existing artifact allowlists do not automatically include them.

## Current instructions for users

**Українською.** У поточній 1.0 вводьте українські запити, але не вважайте їх гарантією мови публікації. У Research явно знайдіть видання через OpenAlex, виберіть конкретний ідентифікатор і запустіть пошук: це обмежена вибірка проіндексованого основного джерела. `python cli.py list --query "український термін"` шукає вже збережену бібліотеку. Імпорт PDF/RIS/BibTeX у наявній праці додає анотації; створення бібліотеки зі своїх файлів — окремий запланований процес. Новий фільтр означає мову метаданих OpenAlex, а не підтверджену мову повного тексту; точні нові команди належать опису реалізованого Draft PR.

**English.** In current 1.0, Ukrainian query text does not guarantee publication language. In Research, explicitly look up a venue via OpenAlex, choose its identity and search a bounded page of indexed primary-source records. `python cli.py list --query "Ukrainian term"` searches the stored library. PDF/RIS/BibTeX import on an existing paper adds annotations; building a library from local files is a separate planned workflow. The new filter means OpenAlex metadata language, not confirmed full-text language; the implementation Draft PR should give exact new commands.
