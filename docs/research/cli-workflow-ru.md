# Практический маршрут: от журнала к сравнению работ

LitBeacon теперь поддерживает маршрут «найти конкретное издание → найти статьи в нём → прочитать и сопоставить методы → экспортировать доказательства». Для работы не нужен LLM. Команды доступны после обновления до изменений из PR #16; номер релиза пока остаётся 0.8.0.

## Что изменилось в CLI

| Команда | Что делает |
| --- | --- |
| `search "запрос"` | Существующий широкий поиск по настроенным источникам |
| `venue lookup "название"` | Онлайн-поиск записей издания в OpenAlex; показывает конкретные идентификаторы |
| `venue search SOURCE_ID "запрос"` | Поиск одной ограниченной страницы статей именно в выбранном издании |
| `list`, `show`, `web` | Существующие способы просмотра общей локальной библиотеки |
| `evidence show ID` | Показывает поля сравнительной карточки и номер её ревизии |
| `evidence update ID fields.json --expected-revision N` | Сохраняет ваши сведения с происхождением и защитой от устаревшей записи |
| `evidence export ID ... --output matrix.md` | Экспортирует выбранные карточки в Markdown; `--format csv` — в CSV |

Для подробной справки используйте `python cli.py venue --help`, `python cli.py venue search --help` и `python cli.py evidence --help`. Новые команды не заменяют старые. Их результаты входят в ту же SQLite-библиотеку; личные заметки, теги и статусы сохраняются.

## 1. Выберите издание и получите статьи

Из каталога репозитория, в активированном Python-окружении:

```sh
python cli.py venue lookup "Computational Linguistics" --limit 10
python cli.py venue search SOURCE_ID "emotion context" --year-from 2023 --year-to 2026 --limit 20
```

Замените `SOURCE_ID` на значение `source_id` вида `S` + цифры, полученное первой командой. Не используйте название как идентификатор. Сверьте название, ISSN/ISSN-L, тип и издателя/организацию: похожие названия могут относиться к разным изданиям. Тип `journal` отличается от `conference/proceedings`, а платформа публикации сама по себе не является журналом.

Ответ — JSON. `paper_ids` содержит локальные номера статей; `newly_stored` — число новых записей; `cache_hit` показывает использование сохранённой страницы. `count` — число совпадений по данным OpenAlex, а `truncated` предупреждает, что текущая страница не охватывает все совпадения. Следующая страница запрашивается отдельно:

```sh
python cli.py venue search SOURCE_ID "emotion context" --year-from 2023 --year-to 2026 --limit 20 --page 2
python cli.py list --status all
python cli.py show 42
python cli.py web
```

Здесь и далее `42` — пример: подставьте номер из `paper_ids`. В браузере откройте существующий Literature inbox. Для поиска по изданиям и заполнения evidence без JSON используйте новую вкладку **Research / Дослідницький стіл**; [веб-сценарий](web-workspace.md).

Поиск использует фильтр источника на стороне OpenAlex, а не отбрасывает чужие журналы после широкого поиска. Однако он ограничен основным источником публикации (`primary_location.source.id`), страницей и покрытием самого OpenAlex; это не гарантия полной библиографии журнала. Результаты новых статей не получают автоматическую оценку научной релевантности: их начальный балл равен нулю, а оценки уже известных статей сохраняются.

Чтобы сначала работать в отдельной библиотеке, указывайте `--db research.sqlite` **перед** названием команды во всех шагах, например `python cli.py --db research.sqlite venue lookup "Computational Linguistics"`. Без `--db` используется ваша обычная локальная библиотека.

## 2. Заполните сравнительную карточку

```sh
python cli.py evidence show 42
```

Выберите поля, которые можете подтвердить: задача, данные, используемый контекст, механизм отбора, метод, базовые модели, метрики, результат и место в источнике. Авторские ограничения заполняйте в `author_limitations`; свои вопросы — в `user_questions`, предполагаемый пробел — в `gap_candidate`. Это разные виды утверждений.

Создайте UTF-8 файл `fields.json`, например с вашим вопросом:

```json
{
  "user_questions": {
    "value": "Проверяли ли авторы отбор контекста при одинаковом токенном бюджете?",
    "origin": "user"
  }
}
```

```sh
python cli.py evidence update 42 fields.json --expected-revision 0
```

`0` подходит для новой карточки. При последующих изменениях подставьте текущую `revision` из `evidence show`. Меняются только переданные поля; предыдущие ревизии сохраняются. Для сведений из аннотации или полного текста укажите `origin` как `abstract_review` или `full_text_review`, реальный `source_ref`, а по возможности `location` и `reviewed_at`. Например, в `location` можно записать «Table 3, p. 7» после проверки именно этой таблицы. Не копируйте выдуманные значения.

Отдельно выставьте `evidence_granularity`: `metadata only`, `abstract reviewed` или `full text reviewed`. Происхождение отдельного поля не повышает автоматически качество всей карточки. Отметка `verified` означает вашу декларацию с источником, а не внешнюю сертификацию программой. Эти команды ничего не отправляют LLM и не переписывают личные заметки.

## 3. Получите материал для обсуждения с руководителем

```sh
python cli.py evidence export 42 43 --output matrix.md --research-question "Помогает ли отбор контекста при фиксированном бюджете?"
python cli.py evidence export 42 43 --format csv --output matrix.csv
```

Подставьте существующие номера. Markdown содержит краткую таблицу и подробные карточки: что известно, откуда взято, где ещё нужна проверка. CSV удобен для дальнейшего ручного сравнения. Незаполненные результаты остаются `not verified`; личные заметки в этот экспорт не включаются.

## Практическая значимость

Для диссертации это основа проверяемого обзора: можно отдельно просматривать специализированные журналы и конференции, связывать методологические утверждения с источниками и готовить сравнительную таблицу для руководителя. Главное преимущество — явное разделение метаданных, прочитанного доказательства и вашей гипотезы. Инструмент не устанавливает новизну и не назначает категории «вперше», «удосконалено», «набуло подальшого розвитку».

[Обзор 20 реальных работ](erc-context-novelty-matrix-2026.md) даёт стартовый набор конкурирующих подходов, три кандидатных пробела и два предложенных эксперимента. В частности, структурный контекст, учёт говорящего и оптимизация длины уже имеют предшественников. Потенциальное отличие стоит искать в проверенном сочетании задачи, структуры обсуждения, бюджета и устойчивости к отвлекающему контексту. Обзор преимущественно основан на аннотациях; это не законченная глава диссертации. Его R01–R20 — документные обозначения, не локальные `paper_ids`; автоматический импорт этих работ не выполнялся.

Для LitBeacon получены повторно используемые адаптер поиска, хранение идентичностей/наблюдений и независимый слой сравнительных карточек. Новая вкладка Research уже использует эти сервисы для локализованного выбора издания и редактирования evidence-карточек в браузере. Дальнейшие полезные шаги: отдельно проверить веб-поиск на живом API, пройти полные тексты ближайших конкурентов, затем провести сравнение при одинаковых токенных бюджетах. Дополнительные форматы экспорта или ограниченное обогащение Crossref возможны отдельными изменениями.

## Ограничения текущего результата

Пользователь подтвердил, что живой CLI API работает на его установке (2026-10-14). Ранее прямые запросы OpenAlex/Crossref в облачной среде были заблокированы прокси (403). Это ограничение данной среды; доступ на вашей машине нужно проверить отдельно, ; пользовательский успех CLI не является независимой проверкой нового веб-поиска. Метаданные издания не удостоверяют рецензирование или актуальную индексацию Scopus/WoS. Ошибки API, пустые результаты и неоднозначный выбор имеют разные статусы. Повторяющиеся ошибки следует проверять через настройки сети/провайдера; менять личные данные для их устранения не требуется.
